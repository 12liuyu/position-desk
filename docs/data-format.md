# 本地数据格式 v1

本文件说明接口，不代表上游账户采集已实现。使用者负责合法取得、核验和及时更新数据。

输入文件名固定为 `account.json`。结构参考 `examples/demo.json`，但真实导入时必须使用 `demo: false`、六位字符串代码、当日真实时间以及自己核对过的数值；**不能只把示例日期改成今天来假装新数据**。

## 顶层字段

| 字段 | 含义 |
| --- | --- |
| `schema_version` | 数字1 |
| `demo` | 本地模式必须为布尔值false |
| `captured_at` | 持仓采集时间，ISO8601且含时区，不是文件复制时间 |
| `session_open` | 上游确认当前是否属于交易会话，必须是布尔值；不确定设false |
| `reference_date` | 完整收盘基准日期，YYYY-MM-DD；盘中不能填当天 |
| `target_date` | 上游确认的计划适用交易日；必须晚于基准日期且未过期 |
| `total_assets` | 总资产，数字 |
| `available_funds` | 可用资金，数字 |
| `market_value` | 持仓汇总市值，数字 |
| `stocks` | 持仓列表；明确空仓才用空列表，不能以空列表代表接口失败 |
| `plan` | 日期和逐股预案对象；暂缺预案用空对象 |

金额检查：逐股 `quantity * current_price == market_value`，持仓市值之和等于总市值，总资产减可用资金等于总市值，允许分币级浮点误差。该契约为简单股票现金账户模型，不适用于有其他资产、负债、冻结款差异的账户；不匹配时不要人为改数通过。

## 持仓行

`code`、`name`、`quantity`、`sellable_quantity`、`cost_price`、`current_price`、`market_value` 必填。
数量为整数且大于0；可卖为0到持仓数量的整数；成本和价格必须为正有限数。拒绝重复代码。

- `stop_loss_pct`：使用者明确选择的成本亏损提醒百分数，例如3表示3%，不是0.03；有效范围(0,20]，只作输入合理性边界，不是风险建议。
- `price_tick`：本版必须为0.01。
- `reference_close`：与顶层基准日期对应的收盘基准，正数。上游负责除权修正与日期核对。
- `quote`：对象，包含同一证券的 `code`、`name`、`price` 和带时区的 `at`。报价时间必须属于当日，不能超前30秒；工作日盘中超过180秒即拒绝。

`current_price` 是持仓采集时用于对账的价格，`quote.price` 可以是之后的报价。两者不必相同，不要用新行情倒写旧账户对账数据。

## 预案

`plan.asof_date`、`plan.trade_date` 分别严格匹配基准日和适用日。`plan.stocks` 按代码索引，各条目必须绑定相同的名称、数量、成本和 `stop_loss_pct`。任一不匹配会隐藏该证券旧预案，但不冒充空仓。

每条预案有1到6个 `scenarios`，每个包含非空的 `title`、`trigger`、`action`、`reason`。标题不得重复；首个情景用于提醒线触发后的展示，编写时应放提醒线处理预案。软件总是另行显示计算得到的提醒线状态，不会认证情景文字的金融含义。

`tone` 支持 `risk`、`positive`、`watch`，用于绿、红、橙标记；不表示情景已触发。

`quick_view` 是简版：`action` 最多24字，`conditions` 为1至3条、每条最多40字的条件，`otherwise` 最多64字。条件按“同时满足”展示。超限或缺失不会截断成交易指令，而显示“简版待核验”，完整内容仍可查看。

`price_levels` 仅列确需标注的价格字符串，例如 `"26.00"`。软件据 `(价位 / reference_close - 1) * 100%` 标注涨跌幅，不处理非价格数字。`facts`、`unknowns`、`sources` 可作为字符串列表供详情页展示。

## 安全更新

外部采集器应完成真实来源核验、完整写入临时文件，再原子替换 `account.json`。应用不修改输入；错误、陈旧或缺字段时暂停，不用历史缓存兜底冒充当前状态。数据变更后点击“重读数据”，或等下一次60秒轮询。无效数据不会结束已有持仓的跟踪。

`--check` 退出码0仅表示本地输入校验通过，不表示预案存在、建议正确、真实账户已经采集或提醒正在运行。
